# Benchmark scenarios

This directory contains the scenario set used in the paper.

```text
data/scenarios.jsonl        2,773 retained scenarios (960 marked in_evaluation_set)
data/filtered_out.jsonl     180 scenarios removed by fixed-orientation screening
data/eval_960.txt           the 960 evaluation-set scenario IDs, one per line
```

The generated images are not redistributed in this repository. The frozen
automatic votes for 68,764 image records are in `analysis/votes.json.gz`; the
reference evaluation implementation is in `evaluation/`.

## How 2,953, 2,773 and 960 relate

1. **2,953 scenarios.** Each CDEval question (Wang et al., 2023) yields one
   scenario. CDEval covers six Hofstede dimensions and seven domains.
2. **2,773 retained.** Every scenario is screened on all six dimensions, not
   only its source dimension. A scenario is removed when its wording already
   fixes an orientation, so a faithful image could not express the opposite
   one. Screening removes 180 scenarios (`filtered_out.jsonl`). The remaining
   2,773 form the benchmark.
3. **960 evaluated.** The experiments use 160 retained scenarios per source
   dimension (960 in total), marked by `in_evaluation_set`. Each evaluation
   scenario is rendered under up to 14 language and cue conditions and
   generated by every system, giving 68,764 images, each scored by three
   verifiers. All 2,773 scenarios come with translations and rendered prompts,
   so the set can be resampled or extended.

| Source dimension | Before filtering | Removed | Retained | Evaluated |
|---|---:|---:|---:|---:|
| PDI | 512 | 25 | 487 | 160 |
| IDV | 472 | 28 | 444 | 160 |
| MAS | 452 | 44 | 408 | 160 |
| UAI | 530 | 27 | 503 | 160 |
| LTO | 485 | 25 | 460 | 160 |
| IVR | 502 | 31 | 471 | 160 |
| **Total** | **2,953** | **180** | **2,773** | **960** |

## `scenarios.jsonl`

One JSON object per line, 2,773 lines.

| Field | Description |
|---|---|
| `scenario_id` | Stable ID, `cdeval_<dim>_<index>`; the index follows the CDEval item order within the dimension. |
| `source_dimension` | The CDEval dimension the scenario was derived from (PDI, IDV, MAS, UAI, LTO, IVR). |
| `value_dimension`, `orientations` | The source dimension's two orientations, with their definitions. |
| `in_evaluation_set` | `true` for the 960 evaluated scenarios. |
| `cdeval_item` | The source CDEval item: `domain`, `question`, `option_1`, `option_2`. |
| `concept` | The value issue shared by the question and both options (concept extraction). |
| `scenario` | The English scenario. Different CDEval items can yield the same sentence (2,745 unique sentences); each keeps its own ID. |
| `translations` | The scenario in Chinese (`zh-CN`), Thai (`th-TH`) and Hindi (`hi-IN`). |
| `prompts` | The full T2I prompt for each of the 14 conditions (below). |

Prompt conditions are keyed `<language>__<cue>`, where `none` means no
geographic cue:

| Language | Conditions |
|---|---|
| English | `en_us__none`, `en_us__us`, `en_us__cn`, `en_us__th`, `en_us__in` |
| Chinese | `zh_cn__none`, `zh_cn__cn`, `zh_cn__us` |
| Thai | `th_th__none`, `th_th__th`, `th_th__us` |
| Hindi | `hi_in__none`, `hi_in__in`, `hi_in__us` |

The six English and Chinese conditions (`en_us__{none,us,cn}`,
`zh_cn__{none,cn,us}`) are evaluated on every system. The other eight are
evaluated on the three commercial API systems.

## `filtered_out.jsonl`

One JSON object per line, 180 lines. Each line has the same `scenario_id`,
`source_dimension`, `cdeval_item`, `concept` and `scenario` fields as above,
plus:

| Field | Description |
|---|---|
| `flagged_by` | The screening model(s) that flagged the scenario: `gemini_3.7_flash`, `claude_opus_5`, or both. |
| `flags` | One entry per fixed orientation: `value_dimension`, `fixed_orientation`, and `quoted_text`, the wording each screener quoted as fixing it. |

Gemini 3.7 Flash and Claude Opus 5 screen every scenario, and the authors
review the union of their flags. A flag counts only when the quoted words leave
no faithful way to depict the opposite orientation. Unresolved choices ("the
choice they made between X and Y"), open reactions ("reacting to"), and roles,
settings or objects named without saying how people act are not flags. Of the
180 removals, 90 are flagged on their source dimension (8 of these also on
another dimension) and 90 only on other dimensions.

## Construction and filtering materials

The prompts that produced this file, and the decision cards used by the
evaluators, are in `materials/construction/`, `materials/filtering/` and
`materials/annotation/`. The evaluation code reads the executed prompts and
schemas from `materials/annotation/` and verifies them against
`materials/manifest.json`.
